# Session: Version 0.2.0

## Request

"bump up the version and you have access to codex cli", then "so you can test
for regressions".

## Changes

Checked the Codex side of the merged Claude Code support with the Codex CLI
before bumping. Three `codex exec` runs used a throwaway `UserPromptSubmit`
hook that pointed at the repository copy of `advisor.py` with its own state
directory, so the installed plugin was left alone:

- On `gpt-6-astra` with a trivial prompt, JEV chose `gpt-5.6-luna` and the hook
  stayed quiet, because a cheaper model is not an upgrade.
- On `gpt-5.6-terra` with a bounded migration prompt, JEV chose
  `gpt-5.6-terra / medium` and the hook stayed quiet.
- On `gpt-5.6-luna` with an architecture prompt, JEV chose `gpt-6-astra / high`
  and the hook returned the warning and the callout, word for word as before.

The captured Codex payload carried `session_id`, `turn_id`, `transcript_path`,
`cwd`, `hook_event_name`, `model`, `permission_mode` and `prompt`, with no
effort field, which matches what the Codex profile expects.

Then bumped both manifests to 0.2.0 and added a test that they stay equal.

## Decisions

- One version number for both hosts. Two numbers would drift, and the hosts
  ship the same script.
- A minor bump, not a patch: Claude Code support is a new capability.
